1. كيف تقرأ هذا الدليل

هذا شرح تعليمي لواجهة مشروع CarRental / Rently كما تظهر في الملفات يوم 14 أكتوبر 2026. اللغة عربية مع إبقاء أسماء الملفات والدوال بالإنجليزية لتتمكن من العثور عليها في المحرر.

يغطي الدليل جميع ملفات المصدر في frontend/src، وملفات تشغيل وبناء الواجهة. يشرح مسؤولية كل ملف، والحالة التي يديرها، وأهم الدوال والعلاقات. لا يكرر كل سطر من الشيفرة؛ الأسطر المتشابهة في الجداول والنماذج تُشرح كنمط واحد، والصور تُشرح بوظيفتها.

فسّرت عبارة «what should to new» على أنها: ما الذي ينبغي أن أعرفه وأتعلّمه؟ لذلك ستجد مسار تعلّم، وتطبيقًا لإضافة صفحة جديدة، وقائمة بما يحتاج إلى تطوير في النسخة الحالية.

الملاحظات عن الوظائف مبنية على قراءة الشيفرة، وليست نتيجة تجربة كل عملية على خادم يعمل. عند ذكر مشكلة توافق محتملة مع API، فهذا يعني أن الواجهة تحتاج إلى مراجعة عقد البيانات قبل الجزم بالنتيجة.

  • ابدأ بالمعمارية والمفاهيم الأساسية، ثم اقرأ المكوّنات وHooks.
  • لفهم طلب HTTP تتبّع صفحة ← adminApi ← api ← الخادم.
  • لتغيير النصوص اقرأ فصل الترجمة، ولإضافة ميزة اقرأ فصل الصفحة الجديدة.

2. الصورة العامة: كيف تعمل الواجهة؟

5. Context: القيم المشتركة

frontend/src/context/AuthContext.jsx

AuthProvider يحتفظ بـ user وloading. عند بدء التطبيق يستدعي getCurrentUser؛ نجاح الطلب يملأ المستخدم وفشله يبقيه null. المتغير active يمنع تحديث الحالة بعد إزالة المزود.

يسمع الحدث rently:logout ليحدّث الواجهة عند انتهاء الجلسة. login يستدعي خدمة تسجيل الدخول ثم يخزن المستخدم في state؛ logout يمسح الجلسة ويعيد user إلى null. signup وverifyEmail يمرران الطلب للخدمة، لكن الخدمة الحالية ترفضهما برسالة توضيحية.

useAuth يقرأ Context ويرمي خطأ إذا استُخدم خارج AuthProvider. لا تعتمد على تعليق إنشاء الحساب في هذا الملف وحده؛ التنفيذ الفعلي في authApi يحدد ما هو متاح.

frontend/src/context/I18nContext.jsx

يقرأ اللغة المحفوظة في المفتاح rently_lang، ويتحقق أنها ضمن اللغات المعروفة؛ الافتراضي en. setLang يحدّث state ويحاول الحفظ في localStorage.

useEffect يحدّث lang وdir على عنصر html. العربية تضبط الاتجاه rtl. useCallback يجعل t مرتبطة باللغة الحالية، وuseMemo يجمع القيمة المشتركة. useI18n يتيح t وlang وdir وlanguages وsetLang.

frontend/src/context/Confirmcontext.jsx

ConfirmProvider يعرض نافذة تأكيد مشتركة. useConfirm يرجع دالة تعطي Promise؛ عند الموافقة تكون true وعند الإلغاء false.

dialog يحتفظ بالنص وتسميات الأزرار وشكل الخطر. useRef يحتفظ بدالة resolve إلى أن يختار المستخدم. handle يغلق الحوار وينهي الوعد. الضغط خارج البطاقة يلغي، وstopPropagation يمنع نقرة داخل البطاقة من إغلاقها.

الاسم الفعلي للملف هو Confirmcontext.jsx؛ راعِ حالة الأحرف عند الاستيراد على Linux. التنفيذ يحتفظ بمحلّل وعد واحد، لذلك لا تفتح عدة حوارات متزامنة.

const confirm = useConfirm();
if (!(await confirm("Delete this vehicle?", { danger: true }))) {

}

frontend/src/components/ProtectedRoute.jsx

يقرأ user وloading من useAuth. أثناء التحميل يعرض مؤشر انتظار، وعند غياب المستخدم يعرض Navigate نحو /login ويحفظ الرابط المطلوب في state.from. عند وجود المستخدم يعيد children.

هذا حارس واجهة. التحقق من دور admin موجود أيضًا في getCurrentUser بخدمة المصادقة؛ صلاحيات البيانات يجب أن يفرضها الخادم.

frontend/src/components/LanguageSwitcher.jsx

يعرض اللغة الحالية وزرًا لفتح القائمة. يقرأ اللغات من useI18n بدل تعريفها مرة ثانية. عند الاختيار ينفذ setLang ويغلق القائمة.

open تتحكم بظهور القائمة، وref يحدد عنصرها. useEffect يضيف مستمعًا للنقر خارج القائمة ولمفتاح Escape ويزيل المستمعات عند الإغلاق أو إزالة المكوّن. aria-expanded وrole يصفان سلوك القائمة لأدوات الوصول.

frontend/src/components/Pagination.jsx

مكوّن عرض يستقبل page وpageCount وtotal وstart وend وsetPage كـ props. يعرض ملخص عدد العناصر ورقم الصفحة وأزرار السابق والتالي، ويعطّل الزر عند حدود القائمة.

لا يحسب التقسيم ولا يطلب بيانات من API. يعيد null عندما total يساوي صفرًا. يأخذ الأرقام من usePagination ويترجم النصوص بواسطة t.

frontend/src/components/GlobalSearch.jsx

نافذة بحث موحدة تفتح من AdminLayout. loadIndex يجلب السيارات والفروع والكتالوج والحجوزات والمراجعات والمستخدمين والأسئلة والإشعارات باستخدام Promise.all، ثم يحولها إلى سجلات فيها type وtitle وsubtitle وto ونص البحث haystack.

norm يحوّل النص إلى حروف صغيرة ويحذف علامات التشكيل اللاتينية، فيطابق aeroport كلمة Aéroport. هذا لا يترجم المحتوى ولا يعالج جميع أشكال الحروف العربية.

عند الفتح يعيد التحميل ويضبط التركيز. useMemo يبحث في أسماء الصفحات وفي البيانات؛ يشترط وجود كل كلمات الاستعلام ويحد نتائج البيانات إلى 30. groups يجمع النتائج حسب النوع مع الحفاظ على ترتيب التنقل.

الأسهم تغيّر النتيجة النشطة، Enter يختارها، وEscape يغلق النافذة. choose يغلق ثم ينفذ navigate. بعض النتائج تفتح صفحة القائمة، ونتيجة السيارة تفتح تعديل السيارة. فشل أحد طلبات Promise.all يُفشل تحميل فهرس البيانات كله في التنفيذ الحالي.

7. usePagination: شرح الحساب خطوة بخطوة

frontend/src/hooks/usePagination.js

PAGE_SIZE يساوي 10. الدالة paginate مستقلة عن React: تأخذ items ورقم الصفحة المطلوب وترجع بيانات التقسيم. pageCount هو العدد مقسومًا على 10 مع التقريب للأعلى وبحد أدنى 1. page يُحصر بين 1 وpageCount.

offset هو عدد العناصر التي يجب تجاوزها: (page - 1) × 10. slice يأخذ الجزء المطلوب دون تعديل المصفوفة. start وend يفيدان في عبارة «عرض 11–20 من أصل 25». عند القائمة الفارغة start وend يساويان صفرًا.

usePagination يحتفظ بـ selection وفيه filterKey وpage. إذا تغير مفتاح الفلتر يستخدم الصفحة الأولى فورًا. وإذا حُذفت عناصر وأصبح الرقم أكبر من آخر صفحة، يصححه. التحديث المشروط أثناء العرض يعيد مزامنة selection؛ لا يُنفذ بشكل غير مشروط.

setPage ينشئ اختيارًا جديدًا مرتبطًا بمفتاح الفلتر الحالي. عند تعدد الفلاتر تستخدم الصفحات JSON.stringify لتكوين مفتاح واحد. لا ترسل كائنًا جديدًا غير ثابت كمفتاح في كل عرض، لأن المقارنة هنا تعتمد على ===.

const pagination = usePagination(
  filteredVehicles,
  JSON.stringify([status, query])
);

return (
  <>
    {pagination.pageItems.map((vehicle) => (
      <div key={vehicle.id}>{vehicle.model}</div>
    ))}
    <Pagination {...pagination} />
  </>
);

8. services/api.js: الاتصال بالخادم

frontend/src/services/api.js

ينشئ Axios instance بعنوان baseURL مأخوذ من VITE_API_URL أو /api، مع مهلة 15000 ميلي ثانية. يحذف الشرطات النهائية المكررة ثم يضيف شرطة واحدة.

TOKEN_KEY هو rently_admin_tokens وSESSION_KEY هو rently_admin_session. readTokens يحاول قراءة JSON من localStorage بأمان. clearSession يحذف المفاتيح ويرسل حدث rently:logout.

request interceptor يضيف Authorization: Bearer access لكل طلب يحمل جلسة، باستثناء المسارات التي تبدأ بـ token/. هذه نقطة موحدة بدل تكرار الترويسة في كل خدمة.

response interceptor يحاول عند 401 تحديث access بواسطة token/refresh/ مرة واحدة للطلب، باستخدام علامة _retry. المتغير refreshRequest يجمع محاولات التحديث المتزامنة في وعد واحد. يتحقق من أن refresh لم يتغير قبل حفظ النتيجة، لتجنب استعادة جلسة انتهت أثناء الانتظار.

إذا فشل التحديث يمسح الجلسة. ينقل detail النصية من الخادم إلى error.message، وعند غياب response يعطي رسالة تعذر الاتصال.

getList يجمع نتائج القوائم: إن كانت الاستجابة مصفوفة يرجعها؛ وإن كانت {results, next} يتابع الصفحات. يعيد بناء رابط الصفحة التالية على مسار API المهيأ بدل استخدام أصل مختلف في next.

const { data } = await api.get("vehicles/12/");
await api.patch("vehicles/12/", { status: "maintenance" });
await api.delete("vehicles/12/");

تعلم الفرق بين 401 وانقطاع الشبكة وخطأ التحقق من الحقول. في المتصفح استخدم Network لمعرفة الرابط والطلب والجواب؛ لا تعتمد على أن الرسالة المعروضة تكشف كل التفاصيل.

9. خدمات المصادقة وعمليات الإدارة

frontend/src/services/authApi.js

asUser يضيف name من first_name وlast_name أو username. getCurrentUser يرجع null عند غياب الرموز، وإلا يطلب users/me/. لا يقبل إلا role يساوي admin، ويمسح الجلسة إذا لم يتحقق ذلك.

login يمسح الجلسة القديمة، يرسل البريد وكلمة المرور إلى token/، يحفظ الرموز، ثم يتحقق من المستخدم. أي فشل بعد حفظ الرموز يمسحها. logout ينظف التخزين.

signup وverifyEmail يرميان خطأ مقصودًا يوضح أن التسجيل العام للمسؤولين والتحقق بالبريد غير متاحين على الخادم الحالي.

frontend/src/services/adminApi.js

طبقة أسماء مفهومة لعمليات الإدارة. كل دالة ترجع البيانات المستخرجة من Axios أو تستخدم getList. بذلك لا تحتاج الصفحة إلى معرفة details الخاصة بالمكتبة.

getAdminStats يطلب dashboard/stats/، لكنه غير مستخدم في لوحة التحكم الحالية. updateVehicleStatus ينفذ PATCH لحالة السيارة. وظائف الكتالوج وإعدادات الموقع معاد تصديرها من localAdminData.

updateReservationStatus يحول confirmed وcancelled وcompleted إلى إجراءات confirm وcancel وcomplete ويرسل POST. الحالات الأخرى تُرفض. markAllNotificationsAsRead يجلب القائمة ثم ينفذ طلبًا لكل إشعار غير مقروء بواسطة Promise.all.

عند التأكيد ينفذ العمليات بالتتابع. وجود id يختار update وغيابه يختار create. أول فشل يوقف الاستيراد ويعرض الصف وعدد المحفوظات. العمليات السابقة تبقى محفوظة؛ لا توجد معاملة واحدة ترجع كل التغييرات للخلف.

الصفحة تعرض السحب والإفلات، حالة المعالجة، جدول أخطاء، وإرشادات القالب. الحجوزات والمستخدمون والمراجعات قابلة للتصدير فقط. الرسائل المحلية مترجمة، أما رسائل الخادم فتصل وفق ما يرجعه الخادم.

File
  → parseReport(text, filename, dataset, t)
  → prepareImport(dataset, records, existing, t)
  → Preview: created / updated / errors
  → Confirm
  → create/update (one request per record)

للتجربة التعليمية ابدأ بملف صغير من الفروع. صدّر البيانات كقالب ثم عدّل سجلًا واحدًا. لا تنشئ بيانات تجريبية في بيئة فعلية دون قصد، لأن زر التأكيد ينفذ حفظًا حقيقيًا.

18. الترجمة والتنسيق والصور

frontend/src/i18n/translations.js

LANGUAGES يحدد en وfr وar واتجاه كل لغة. النص الإنجليزي نفسه هو مفتاح الترجمة. translations يحتوي قواميس الفرنسية والعربية؛ الإنجليزية ترجع المفتاح نفسه عادة.

translate يتحقق من أن المفتاح نص، ويختار صيغة الجمع بواسطة Intl.PluralRules عندما values.count رقم. يبحث عن المفتاح مع لاحقة الجمع، ثم المفتاح الأصلي، وإلا يرجع النص كما هو. أخيرًا يستبدل المتغيرات مثل {name} و{count}.

إضافة نص جديد تتطلب استعمال t في JSX وإضافة المفتاح نفسه في قاموسي fr وar. المطابقة حرفية: تغيير النقطة أوالحروف أوعلامة الحذف قد يجعل الترجمة لا تظهر.

const { t } = useI18n();
<h1>{t("Reports & Data")}</h1>
<p>{t("Showing {start}–{end} of {total}", {
  start: 1, end: 10, total: 25
})}</p>

20. مثال كامل: ماذا يحدث عند حذف سيارة؟

  • يعرض AdminVehicles قائمة vehicles بعد اكتمال getVehicles.
  • ينقر المستخدم زر الحذف، فيُستدعى handleDelete(id).
  • useConfirm يعرض الحوار ويعيد وعدًا؛ الإلغاء ينهي الدالة دون طلب حذف.
  • عند الموافقة ينادي handleDelete خدمة deleteVehicle(id).
  • adminApi يستدعي api.delete لمسار vehicles/{id}/.
  • request interceptor يرفق access token. إذا رجع 401 قد يحاول api تحديث الرمز وإعادة الطلب مرة واحدة.
  • بعد النجاح تستعمل الصفحة setVehicles(prev => prev.filter(...)) لإزالة السيارة محليًا.
  • تُعاد حسابات التصفية والتقسيم. إن أصبحت الصفحة الأخيرة فارغة يصحح usePagination رقم الصفحة.
  • Pagination يعرض الملخص الجديد. لا يحتاج React إلى إعادة تحميل الصفحة كلها.

الفكرة نفسها تتكرر في الأسئلة والفروع والمراجعات: حدث من المستخدم ← تأكيد عند الحاجة ← خدمة ← تحديث state ← عرض جديد. الفرق هو الحقول ونقطة الاتصال.

21. كيف تضيف صفحة جديدة؟

مثال تعليمي لإضافة صفحة Help داخل الإدارة. هذا المثال مقترح للتعلّم، ولم يُطبّق على ملفات التطبيق ضمن إعداد هذا الدليل.

// frontend/src/pages/admin/AdminHelp.jsx
import { useI18n } from "../../context/I18nContext";

export default function AdminHelp() {
  const { t } = useI18n();
  return (
    <div>
      <h1>{t("Help")}</h1>
      <p>{t("Contact the rental team for help.")}</p>
    </div>
  );
}
  • في App.jsx أضف import للمكوّن ثم Route داخل /admin بمسار help.
  • في NAV_SECTIONS داخل AdminLayout أضف رابط /admin/help مع label وأيقونة من Lucide.
  • أضف مفاتيح Help ونص الوصف في fr وar داخل translations.js.
  • إن احتاجت الصفحة بيانات خادم، أنشئ دالة في adminApi ثم loading وerror وstate في الصفحة.
  • أعد استخدام فئات CSS الموجودة والمكوّنات المشتركة. لا تضع الاتصال بالخادم داخل Pagination مثلًا.
  • اختبر الرابط مباشرة، والتنقل من القائمة، والعربية، وحالة عدم تسجيل الدخول، ثم شغّل البناء.
// App.jsx — inside the /admin parent Route
<Route path="help" element={<AdminHelp />} />

// AdminLayout.jsx — inside a NAV_SECTIONS items array
{ to: "/admin/help", label: "Help", icon: Info }

يلزم أيضًا استيراد Info إذا اخترته. عند استدعاء Hook، ضعه في المستوى الأعلى للمكوّن؛ لا تناده داخل شرط أوحلقة أوevent handler.
